## ก่อน / หลัง

**ถ้าไม่มีตัวนี้:**

```
คุณ   ทำให้ปุ่ม save โผล่บนมือถือหน่อย
AI    แก้ให้แล้วครับ ตอนนี้ปุ่มขึ้นแล้ว
```

ไม่ขึ้น ไม่มีใครเปิดหน้าเว็บไปดูเลย คุณมารู้พรุ่งนี้ จากปากผู้ใช้

**ถ้ามีตัวนี้:**

```
คุณ   ทำให้ปุ่ม save โผล่บนมือถือหน่อย
AI    แก้ให้แล้วครับ
คุณ   ขอดูหน่อย
AI    เปิดหน้าเว็บไปดูแล้ว ปุ่มยังโดนคีย์บอร์ดบังอยู่
      ยังไม่ผ่าน — ขอเปิดงานใหม่
```

นี่คือทั้งหมดของมัน AI ต้องไปดูของจริงก่อนถึงจะพูดคำว่า "เสร็จ" ได้ และถ้าดูไม่ได้
มันต้องบอกคุณ ที่เหลือในนี้คือนิสัยเดียวกันนี้ เอาไปใช้กับงานแต่ละแบบ

และพวกนี้ไม่ใช่ตัวอย่างสมมติ ทุกกฎในนี้แลกมาด้วยข้อบกพร่องจริง:

| สิ่งที่เกิดขึ้นจริงในโปรเจกต์ต้นทาง | กลายเป็นกฎข้อไหน |
|---|---|
| ช่อง URL ตัดด้วยตัวอักษร `s` เพราะ backslash หายไปตัวเดียว อยู่บน production และ **ไม่เคยทำงานถูกเลยสักครั้ง** | การแก้ที่ไม่แมตช์อะไรเลย กับ probe ที่แมตช์กว้างเกิน คือความผิดพลาดเดียวกัน |
| regex ที่ตายแล้วทำให้รอบซ่อมยิง **ทุกครั้งที่ generate** จ่ายสองเท่า แล้วทิ้งผล | ค่าใช้จ่ายอ่านจาก ledger ไม่ใช่จากเจตนา |
| ดราฟต์ออกมายาว **13% ของเป้า** ใต้ commit ตกแต่งหน้าจออีกเจ็ดครั้ง | รีวิวต้องหมุนบทบาท บทบาทเดียวมองข้ามตัวเองไม่ได้ |
| การแก้สามครั้ง **ไม่แมตช์อะไรเลยเงียบๆ** แล้วรายงานว่าเสร็จ | รายงานไม่ใช่หลักฐาน |

## ติดตั้ง

แบบ plugin จะอัปเดตง่ายกว่า:

```
/plugin marketplace add neckttiie090520/nzs-skills
/plugin install nzs-skills@nzs-skills
```

หรือก๊อปไฟล์เอง ถ้าอยากอ่านก่อน — ซึ่งควรอ่าน เพราะนี่คือคำสั่งที่ agent จะทำตามบนเครื่องคุณ:

```bash
git clone https://github.com/neckttiie090520/nzs-skills.git
cp -r nzs-skills/skills/* ~/.claude/skills/        # ใช้ได้ทุกโปรเจกต์
cp -r nzs-skills/skills/* .claude/skills/          # หรือเฉพาะโปรเจกต์นี้
```

**แล้ว restart Claude Code** skills, plugins และ MCP server ถูกอ่านตอนเปิด session
อะไรที่ติดตั้งระหว่างทางจะอยู่บนดิสก์แต่ไม่ถูกโหลด ขั้นนี้แหละที่ทำให้การติดตั้งที่ถูกต้อง
ดูเหมือนพัง

จากนั้นในโปรเจกต์ไหนก็ได้:

```
/nzs-start อยากทำ rate limiting ให้ public API
```

รันครั้งแรก `method-onboard` จะเขียน `.method/config.yml` ให้ ทุกอย่างที่ขึ้นกับโปรเจกต์อยู่ใน
ไฟล์นั้น — คำสั่ง verify, สื่อที่ใช้พิสูจน์, งบ, references, ระดับโมเดล — เพราะแบบนี้ **จึงไม่มี
skill ไหนในรีโปนี้ระบุชื่อ framework, ฐานข้อมูล หรือสกุลเงินเลย** ย้ายไปโปรเจกต์อื่นใช้ได้ทันที

## มันทำงานยังไง

![flow: คุณสั่ง nzs-start วาง stack เครื่องมือไปเอาหลักฐาน ไม่มีหลักฐานก็ไม่ผ่าน](docs/assets/flow.svg)

1. **คุณสั่ง** ภาษาคนปกติ ภาษาไหนก็ได้
2. **`nzs-start` คืน stack ไม่ใช่เมนู** router ที่ยื่นตัวเลือกสามอันให้ คือ router ที่โยน
   การตัดสินใจกลับมาให้คุณ
3. **skill ส่งเครื่องมือไปดูของจริง** — DOM จริงสำหรับคำอ้างเรื่องการแสดงผล, แถวจริงสำหรับ
   การบันทึก, ledger สำหรับค่าใช้จ่าย, exit code ของคำสั่งสำหรับ build
4. **ไม่มีหลักฐาน = กลับเข้า stack** ไม่ใช่ "เสร็จ" อะไรที่พิสูจน์ไม่ได้จะรายงานว่า
   *ลองแล้ว แต่ยังพิสูจน์ไม่ได้ — เพราะเหตุนี้*

## สองชั้น

**Entry points** — คุณเรียกเอง ทำหน้าที่คุมงาน

| skill | ทำอะไร |
|---|---|
| **`nzs-start`** | รับงานมา แล้วตอบเป็น *stack* ว่าจะใช้ skill ไหนเรียงยังไง จบงานเมื่อไหร่ |
| **`nzs-goal`** | เขียนพรอมต์ `/goal` กับไฟล์แผนที่ loop อ่านซ้ำทุกรอบ ออกแบบมาให้ "จบได้" |
| **`nzs-grill`** | แก้ทุกแขนงเอง — spawn subagent ไปค้นคว้า หรือตั้งคณะตัดสิน แล้วปิดท้ายด้วยชิ้นงานจริง |
| **`nzs-panel`** | คนนอกที่มี bias ประกาศไว้ชัด, CTO เรื่องมาก, และ senior ที่มาตบทั้งคู่ |
| **`nzs-setup`** | ติดตั้งทั้งสภาพแวดล้อม แล้ว *พิสูจน์* ว่าแต่ละตัวใช้งานได้จริง |
| **`nzs-handoff`** | ย่อ session ยาวให้ agent ตัวถัดไปทำต่อได้จริง |
| **`nzs-learn`** | บันทึกสิ่งที่ได้ผล, *รูปแบบ* ของความผิดพลาด, และรสนิยมของคุณ ลง engram |

**Disciplines** — โมเดลหยิบใช้เอง หนึ่งตัวทำหนึ่งเรื่อง ให้จบ

| ขั้น | skills |
|---|---|
| หลักการ | `method-evidence` · `method-onboard` |
| เก็บข้อมูล | `method-research` · `method-clone` · `method-extract` |
| ตัดสินใจ | `method-decide` · `method-cost` · `method-record` · `method-postmortem` · `method-scope` · `method-discovery` · `method-ideas` |
| สร้าง | `method-plan` · `method-code` · `method-guard` · `method-harden` |
| ตรวจ | `method-review` · `method-debug` · `method-verify` · `method-design` |
| ความปลอดภัย | `method-security` · `method-threat` · `method-secrets` · `method-web-security` · `method-ai-security` |
| ส่งขึ้นจริง | `method-ship` |
| คุมทั้งงาน | `method-run` — ไล่ฟีเจอร์ทั้งตัวผ่านทุกขั้นข้างบน |

skill ชั้นบนเรียก discipline ได้ แต่ **ห้ามเรียก skill ชั้นบนด้วยกันเอง** — กฎข้อนี้คือสิ่งที่ทำให้
โมเดลไม่สับสนว่าควรเรียกตัวไหน

## มันบังคับอะไรบ้าง

- **หลักฐานมาก่อนคำพูด** อ่าน diff แล้วบอกว่าแก้แล้ว ไม่นับ ต้องไปพิสูจน์ที่ DOM, ที่ไฟล์ CSS
  ที่ build ออกมา, ที่ ledger, ที่แถวข้อมูลจริง
- **guard เกิดตอนบั๊กชนิดเดิมโผล่ครั้งที่สอง** — และยังเชื่อไม่ได้จนกว่าจะ *เห็นมันแดง* ตอนแกล้ง
  ทำให้พัง แล้วเขียวตอนคืนค่ากลับ
- **ตัวเลขเพดานห้ามเข้าข้างตัวเอง** เพดานไม่ใช่การพยากรณ์ ไม่รู้ค่าให้แสดง null ไม่ใช่ 0
  ค่าใช้จ่ายที่โชว์ให้ปัดขึ้น
- **งานที่ตัดสินใจไม่ทำ ต้องบันทึกพร้อมราคาของมัน** จะได้ไม่มีใครมานั่งคิดใหม่
- **งบมีแต่ลดลง** จะขอขึ้นต้องเขียนเหตุผลไว้ใน diff
- **ตรวจ production ก่อน push ที่ต้องพึ่งมัน** ไม่ใช่หลังจากนั้น
- **ปุ่มทุกปุ่มต้องทำงานจริง** ห้ามมี UI สำหรับพฤติกรรมที่ฝั่ง server ยังไม่มี

## จุดอ่อนที่รู้ตัว

ประตูกันการแสดงละคร **ยังตรวจตัวเองอยู่** โมเดลติ๊กช่องเองได้ และแปะผลลัพธ์คำสั่งที่แต่งขึ้นเองได้
ไม่มีใครจากข้างนอกมาเป็นพยาน `nzs-panel` คือสิ่งที่ใกล้เคียงพยานภายนอกที่สุดที่มี และมันยังไม่พอ

การบังคับให้ผู้รีวิวอิสระรันซ้ำสำหรับข้ออ้างที่สำคัญ คือการตัดสินใจที่ยังค้างอยู่

เขียนไว้ตรงนี้ ไม่ซ่อน เพราะวิธีทำงานที่ปิดจุดอ่อนตัวเอง ก็ผิดกฎข้อแรกของตัวเองไปแล้ว

## รีโปนี้บังคับใช้กฎกับตัวเองด้วย

ชุดที่สอนเรื่อง guard ที่รันได้ แต่ตัวเองไม่บังคับอะไรเลย ก็เป็นแค่คำบรรยายถึงวินัย ไม่ใช่ตัววินัย
เพราะงั้น:

```bash
node scripts/validate.mjs --verbose
```

ไม่มี dependency ตรวจสัญญาของ frontmatter, ตรวจว่าทุกการอ้างถึง skill อื่นมีอยู่จริง, ตรวจว่า
ทุก entry point เข้าถึงได้จาก router และมี command, ตรวจว่า README ทั้งสองภาษาครอบคลุมครบ,
ตรวจว่าไม่มีสตริงหน้าตาเหมือนคีย์หลุดเข้ามา และตรวจว่า **ไม่มีการเขียนจำนวนนับลงในเนื้อความ**

ทุกข้อมีอยู่เพราะข้อบกพร่องนั้นเกิดที่นี่มาก่อน และทุกข้อผ่านการทดสอบด้วยการแกล้งทำให้พัง:
ทำให้เสีย เห็นมันแดง คืนค่ากลับ เห็นมันเขียว CI รันแค่ตัวนี้ ไม่มีอย่างอื่น

## มันทำงานคนเดียวไม่ได้

skill เป็นตัวตัดสินว่า **อะไรนับเป็นหลักฐาน** ส่วน tool คือ **วิธีที่คุณไปเอาหลักฐานนั้นมา**
`method-verify` บอกว่าคำอ้างเรื่องการแสดงผลต้องพิสูจน์ที่ DOM — Playwright คือตัวที่เปิด
เบราว์เซอร์ `nzs-learn` บอกว่าบทเรียนต้องอยู่รอดข้าม session — engram คือตัวที่เก็บ

**[คู่มือระบบนิเวศ](docs/ECOSYSTEM.th.md)** ครอบคลุมเครื่องมือทุกตัวที่ใช้ร่วมกัน — แต่ละตัว
คืออะไร ได้อะไร ใช้ยังไง **พังตรงไหน** พร้อมท่าที่ควรจำ use case ตั้งแต่ต้นจนจบ และกรณีศึกษา
ที่เป็นที่มาของกฎทุกข้อ

ในรายการมีเฉพาะเครื่องมือที่ขั้นตอนติดตั้ง **ลงแล้วพิสูจน์ได้ว่าใช้งานได้จริง** อะไรที่ต้องให้คน
เปิดเบราว์เซอร์ไปสมัครแล้วก๊อปคีย์กลับมา ตัดออก ด้วยหลักการเดียวกับทุกอย่างในนี้:
อย่าอ้างสิ่งที่ตรวจไม่ได้
